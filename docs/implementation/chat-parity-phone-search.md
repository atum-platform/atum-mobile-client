# Phone chat parity search and filters

ML3 covers the S1 plain personal search provider, the S2 device index and source, and S16's unread/favourites projection. The lane is partly built until Home adopts the contracts below, the assembled Xcode project includes the source, and the interop checks pass.

## SDK and desktop contracts

- S1 shares `LiveCompanySearchTransport` and `LiveMatrixSession.companySearchEndpoint()` in `ios/App/Company/CompanySpaceMatrix.swift`. The transport does authenticated Matrix v3 search with an ephemeral session, refused redirects and a custody check. The Matrix v1.19 search request carries a nonempty `room_events.filter.rooms` list on every page. The phone's pinned FFI has no homeserver search binding.
- The selected SDK is 26.10.15-atum.2 at `66c18d378d44d9ad61946f08b926514cccb14fb5`, built from Rust `97a1589b70bd122c1d66e0d68ea008d8554076a5` with the producer patch. The generated `matrix_sdk_ffi.swift` exposes `Client.searchService()`, `SearchService.setQuery` and its result subscription, `Client.runSearchBackfill`, `ClientBuilder.withSearchIndexStore` and SDK event focus. The [producer source receipt](https://github.com/atum-platform/atum-matrix-rust-components-swift/blob/66c18d378d44d9ad61946f08b926514cccb14fb5/patches/atum-build-receipt.json) identifies the linked artifact.
- The pin's Rust [local message search](https://github.com/matrix-org/matrix-rust-sdk/blob/97a1589b70bd122c1d66e0d68ea008d8554076a5/crates/matrix-sdk/src/message_search.rs) scans local indexes across joined rooms and resolves result content from the event cache or by event ID. The term stays in the local index lookup. A missing cached hit can cause an event-ID request. Private ciphertext backfill runs separately from query entry. The FFI exposes neither a per-query room filter nor an index-wide count or oldest-indexed watermark. Atum filters results to currently visible joined encrypted rooms and reports measured match coverage. The SDK itself also indexes ordinary room history. Older plain events in a room that later enabled encryption can appear in the local history of that private room since the pin's result projection lacks original wire encryption metadata.
- [Desktop #158](https://github.com/atum-platform/atum-desktop/pull/158) at `3eca77b15a454116a48eaf4b4ccface1b5c8f033` establishes literal personal search, current room membership, ignored sender exclusion, one continuation for an empty first page, and room/event/thread identity. Desktop S2 currently searches already-loaded decrypted history. [Desktop #154](https://github.com/atum-platform/atum-desktop/pull/154) at `49e7b533030366aead94f078801401ebe2322942` establishes single selection, availability computed before the text filter, and fallback to All. Phone S16 implements All, Unread and Favourites from its existing row projection. The adjacent #155–157 contracts retain homeserver delivery, group/thread placement and text search separate from rich content admission.

## Home integration for Opus

1. Create one `GlobalChatSearch<Plain, Device>` per current live session. `Plain` is Home's existing people, company-message and company-file results plus the optional `PersonalMessageSearch.Page`. `Device` is an optional `LocalSearchSource.Page`. Combine the remote providers inside the controller's plain closure as structured children. Every remote entry checks its supplied `isCurrent()` immediately before dispatch and again before using results. Retire the independent Home people/messages/files query tasks. Any local room-name matching uses the plain scope only.
2. The controller's `input` identifies the field binding. Capture that value in the setter and call `submit(_:for:)`. On scope change call `reset(to:)` synchronously, bind the new token and read `query` from the engine. `reset` clears the old field, cancels pending debounce and sources, invalidates old field writes and clears published results. Observe `onChange` from the Home presentation owner. Reset on dismiss, replace the engine on account/session change, and guard both plain and local source construction against stale live sessions.
3. From the current session use `personalMessageSearch(allowsRoom:)`. It enumerates all SDK-known rooms. Supply the canonical Personal visibility predicate independently of unread, favourites, text or presentation paging. Include joined human DMs/groups, assistant DMs and app chats. Skip hidden/deleted rooms, company-bound rooms and unknown workspace classifications, including company private-assistant working rooms. The source independently checks live SDK membership, space type and known encryption. Use each source's `retained` against current eligibility at render time. Revalidate company hits through their existing binding and eligibility service.
4. Use `LocalSearchSource(session:roomIDs:)` with the visible personal and authorized company chat IDs. Exclude company private-assistant working rooms and local deletions. The source verifies custody, device-key continuity, joined membership and known encryption. `observeRedactions(for:onChange:)` watches the displayed rooms and tells Home to discard the page and refresh. Capture the current input/generation in that callback. Membership, locally hidden rooms, and cached ignored-user changes should also invalidate or filter the displayed page. Call `startBackfill()` once on entering the foreground device scope, before typing. Call `stopBackfill()` and `stopObservingRedactions()` on leaving that scope, backgrounding, dismissing, or replacing the session.
5. Render message hits grouped by room with the newest hit first. The canonical roster supplies preferred room names and sender presentation. Use only company source labels. `ChatSearchText.occurrences` can locate matches in the snippet. Personal server coverage has eligible, searched and known-encrypted room counts plus truncation. Track company coverage separately until that provider returns measured counts. Local coverage has eligible private rooms and the number of rooms and oldest timestamp represented by the returned matches. The oldest matching timestamp is evidence about those matches. Total index coverage stays unknown. Handle unavailable/error separately from a successful empty result and explain partial private history within the single coverage line.
6. Use `ChatRoomListFilter` section by section over the existing rows in their existing order. Build `Row` from `HomeRow.badgeInput`, `isPinned` (Matrix `m.favourite`), and a real joined and openable room with no placeholder or invite. Calculate `available` on the unfiltered projection and use `effective` for stale choices. Keep section IDs and the original unfiltered scroll anchor so All can restore it.

### Exact event placement

Capture the current search `generation` and validate selection against the session and current scope. Call `confirmSearchTarget` with the original hit and a live room gate. It rechecks the SDK room before and after awaits, confirms the exact event ID, sender and thread root, rejects vanished/redacted/non-text events, and checks the cached ignore list. Company hits should keep their existing binding verification and use their room, event and thread IDs for placement.

For an already loaded event, scroll by its exact event ID in the current transcript generation. For an unloaded event, the source exposes `ChatSearchEventTarget.timelineFocus(hideThreadedEvents:)`, which produces the SDK's `.event` focus with automatic thread detection. Build a separate focused timeline through `Room.timelineWithConfiguration`, then place and highlight the matching row in that generation. A thread reply retains its reply ID for focus/scroll and its root ID for thread routing. Use the selected room/thread read policy, avoid moving the main read marker while inspecting historical context, and provide a path back to the live transcript. A room or source generation change invalidates a pending placement.

### Index custody and lifecycle

`MatrixLocalSearchStore` derives a separate high-entropy HMAC key from the per-generation random Matrix custody passphrase protected by the existing device-only Keychain. It always supplies that key to the SDK. The path is below the existing generation's backup-excluded cache; the existing sign-out transaction quarantines and purges the generation and deletes the custody secret. A different account/device/generation has a different path and key. A resumed runtime with mismatched device keys admits no private results. No App Group change, duplicate credential record, custom index, or producer pin change is required.

The index receives native cache updates and the Rust index applies redaction removals. A new query gets a fresh SDK handle and validates returned content, membership, visibility and cached ignores. A local Delete hides the room immediately through the canonical roster gate. Index storage is generation-owned and is reclaimed on sign-out. The producer does not expose per-room index deletion at this pin.
