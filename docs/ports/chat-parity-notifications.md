# Phone room notifications

ML2 S3 engine. The existing mute action sets Off, and unmute restores the room's Matrix default. The four-choice settings UI and the live delivery and cross-client checks are pending.

## Matrix and Atum policy

The phone calls the native notification settings on the current Matrix session. All maps to `allMessages`, Mentions & keywords to `mentionsAndKeywordsOnly` and Off to `mute`. The SDK writes room rules for the first two choices and a room-scoped override for Off. The restore call removes the room-specific mode. Reads report the effective mode and whether it is inherited. The SDK receives the actual number of joined members and the room's encryption state to select the inherited default. The SDK delegate refreshes reads after `m.push_rules` sync, and room info updates cover changes to encryption or membership.

The Matrix event-ID-only pusher and homeserver count projection keep their existing behavior. After the notification SDK admits an event, the phone's service extension can suppress a Team Space alert using the synced desktop account data. Quiet hours and quieter thread levels apply under either an inherited or explicit room mode. The former account level is the default for threads. A pre-parity channel preference applies while the room is inherited. Direct mentions and authorized room-wide mentions count as attention. The extension also recognizes participation visible via the SDK's cached thread root or latest reply. The desktop can consult its in-memory thread event list, so a previous reply that is absent from the phone's thread summary may be quiet on phone.

An explicit action in a Team Space room writes the native mode first, then retires that room's legacy override if present. Retirement uses the desktop's SHA-256 per-channel event type and version-2 `inherit` record. It reads the relevant account data from the homeserver and confirms the written revision. No migration runs during sign-in. One phone session serializes changes to the same room, while different account-data targets remain independent. Matrix writes are last-write-wins across devices. A partial write can leave the new Matrix rule in place while the old Atum preference still applies to an inherited mode. The user can retry the same room choice. Later restores after confirmed retirement cannot revive the old preference.

The pinned native writer can delete compound override and underride rules that refer to a room. The phone checks the SDK's synced push rules before mutation and returns `customPushRules` when native changes would remove a separate filter. Ordinary native room modes and room-only mute overrides are writable. ## UI contract

- Read `model.notificationSettingsSession` for the active joined room. It is nil until the current session is ready and its initial sync completed. Key the sheet's observation task by session identity and room ID. Present settings for a room the existing chat or Team Space model allows to open.
- Await `session.observeRoomNotificationSettings(roomID:onChange:)` inside that task. The closure receives `ChatNotificationSettings` on the main actor, starting with the first complete SDK read. Repeated snapshots are coalesced. Cancelling the task detaches the SDK settings delegate and room-info subscription. The one-shot equivalent is `roomNotificationSettings(roomID:)`.
- Use `selection` to mark the current choice and `effectiveMode` to show what an inherited default actually does. `isInherited` distinguishes explicit All from inherited All. Use `hasEncryptedMentionCaveat` with the Mentions & keywords option when the encrypted-event push rule is unavailable or disabled.
- Await `session.setRoomNotificationChoice(roomID:choice:)` with `.set(.all)`, `.set(.mentionsAndKeywords)`, `.set(.off)` or `.restoreDefault`. Keep the confirmed snapshot visible while writing and until the synced snapshot arrives. Track the in-flight action in the presentation. The engine rejects overlapping changes to the same room with `changeInProgress` and protects separate Matrix filters with `customPushRules`. A thrown `legacyPreferenceNotRetired` means the native write returned successfully but the Atum cleanup needs a retry. Let the same action be retried even when it is now selected.
